# Frontend Dashboard — V14

V14 includes a production-oriented, self-contained browser dashboard in `frontend/`.

## Why two UIs?

- **Frontend dashboard:** operational read-only control plane for PIT readiness, dataset coverage and validated paper signals.
- **Streamlit:** exploratory research interface for model experimentation and offline analysis.
- **Android:** client interface for the signal/research API.

## Safety behavior

The dashboard never creates a signal from a raw probability supplied by a browser. It reads only the published-signal artifact generated by the validated pipeline. If required PIT layers are missing, the dashboard displays `PIT BLOCKED` and `NO SIGNAL`.

## API endpoints

- `GET /dashboard` — dashboard HTML
- `GET /api/dashboard/overview` — PIT/publication status
- `GET /api/dashboard/signals` — read-only published paper signals
- `GET /api/health` — service health

The legacy `/signal` endpoint is explicitly marked `research_only` and rejects non-research sources. Production publication must originate from the validated OOS/PIT pipeline.
